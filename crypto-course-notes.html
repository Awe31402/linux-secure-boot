§1密碼學在解決什麼問題

§1.1 三個主角：Alice、Bob、Eve

整門課會一直用這三個人當例子：

角色 身分 也可以想成
Alice 送訊息的人 瀏覽器
Bob 收訊息的人 web service
Eve 攻擊者 網路上任何偷聽的人

故事是這樣：Alice 想傳一則訊息 M 給 Bob，但她跟 Bob 之間沒有直接的實體連線。 訊息一旦上了網路，你根本不知道它會被routing 到哪些節點才到 Bob 手上。

Eve 想做兩件事：偷看內容，有時候還想改掉訊息。 整門課就是在想辦法讓他做不到。

💡 老師強調可以把 Alice/Bob 代換成應用程式或行程，不一定是人。 之後講協定的時候這個代換很有用。

§1.2 網路本來就是不安全的

老師用 Wireshark 這個免費軟體來說明「偷看有多容易」：

平常：你的網路卡只會撿起 MAC address 是自己的封包，其他的丟掉。

裝了 Wireshark 之後：你等於叫網卡把飄過去的封包全部收起來。 用 Wi-Fi 的話，傳輸媒介是空氣，封包就在你周圍飛。

老師建議的練習：在實驗室（有線網路）跑跑看，你會看到同實驗室同學 經過 gateway 的流量。再往上想 —— 如果在 ISP 等級（例如中華電信）跑這個， 那是幾百萬使用者的流量。

這個練習真正的重點：你會發現有些流量的內容你讀得懂。 那些就是沒有做好加密的 legacy 軟體或 app。看到這個，你就會懂為什麼需要密碼學。

⚠️ 字幕在這裡意思反了。 字幕寫成「很多流量有加密所以你讀得到內容」， 原意是「因為那些沒有加密，所以你讀得到」。

⚠️ 字幕辨識錯誤：water shark / 水鯊 = Wireshark。

⚠️ 這是課堂舉例，用來說明風險。不是教你去看別人的流量 —— 那有法律問題。

來源：影片一

§1.3 密碼學的定位：保護其他東西的一層

老師給了一個很好記的定義：

密碼學是一個「用來保護其他物件」的物件。（用軟體的角度看）

放進 OS stack 就清楚了：

┌─────────┬─────────┬─────────┐
│  App 1  │  App 2  │  App 3  │   ← 你以後會寫的東西
├─────────┴─────────┴─────────┤
│         OpenSSL             │   ← 密碼學函式庫（就是這一層）
├─────────────────────────────┤
│         TCP/IP              │   ← 只負責把東西送到
└─────────────────────────────┘

為什麼要有中間這層：TCP/IP 只管把訊息送出去，完全不管內容安不安全。 所以想保護訊息 M，得在丟給 TCP 之前先自己加上保護。 OpenSSL 這類函式庫就是在補這個縫。

不同 OS 有各自預設的函式庫，OpenSSL 只是最常見的一個。

§2密碼學的目標：CIA

§2.1 C — Confidentiality（機密性）

最直覺的一個：只有被授權的人能知道 M 是什麼。

回到 Alice → Bob 的圖：這則訊息是要給 Bob 的，所以唯一被授權的是 Bob。 Eve 不該讀得到。

順帶區分一個容易混的詞：Privacy（隱私）

兩者的目標都是「防止未授權存取」，但 privacy 更複雜一層：

管什麼
Confidentiality 內容不被未授權的人讀到
Privacy 控制誰能存取哪些資訊，以及他們能對這些資訊做什麼

有點像 access control，但更進一步。難點在後半段： 你可以控制誰在什麼時候拿到資料，但很難管他拿到之後做什麼。

老師說這門課不會多談 privacy。 等講到 secure election system（安全選舉系統） 的設計與安全性證明時， 才會回頭談這個方案怎麼保護使用者隱私。

來源：影片二

§2.2 I — Integrity（完整性）

問的問題：訊息中途有沒有被改過？

光有加密還不夠。就算 Eve 讀不懂內容，他還是可能把整則訊息換掉， 或者改掉其中幾個 bit。

跟 CRC 的差別（考試很可能考這個對比）

CRC / error-correcting code 密碼學的 integrity check
出身 資訊理論 密碼學
誰在用 TCP/IP 等協定 數位簽章、MAC 等
防什麼 雜訊造成的傳輸錯誤 有人故意竄改
強度 改的 bit 數夠巧就矇混過關 改一個 bit 都抓得到（以極高機率）

老師用下載檔案當例子：下載完，你要確定傳輸過程中沒有任何 bit 被翻掉。 CRC 只能告訴你「沒有傳壞」，不能告訴你「沒有被人動手腳」。

支票的類比

紙本支票怎麼驗真？靠手寫簽名，或（台灣的做法）印章。銀行比對留存的樣本。

老師還講了自己的糗事：印章弄丟過好幾次，後來又找到， 結果不小心拿舊印章去辦文件，只好跑一趟銀行處理新舊印章的更換。

問題：簽名可以被模仿。電影裡就有人有這種本事。

數位簽章不一樣：

它不是文件上的一張圖或一個符號。 它會把整份文件的所有 bit 拿去做計算，把計算結果留在數位文件上。

所以想偽造一張新支票、又要讓簽章對得上，計算上非常困難。 這就是為什麼數位支票比紙本支票安全得多。

§2.3 A — Authentication（認證）

拆成兩種，這個分法要記熟：

（1）Data origin authentication（資料來源認證）

收到東西之後，確認它是誰送的。

Bob 收到一封訊息，上面寫著「Alice」。但 Bob 要能確認真的是 Alice， 不是 Eve 冒充的。如果驗不過，Bob 就把訊息丟掉，不理它。

（2）Entity authentication（實體認證）

雙方互相證明「我真的是我宣稱的那個人」。

為什麼不總是用雙向的？

老師用連 Gmail 的例子講清楚了：

假設你連到一個公開的 web service，不需要帳號密碼。 這時你在乎的只有一件事：這真的是我要連的伺服器嗎？不是別人假冒的？

伺服器不會反過來質問一個匿名訪客「你是誰」—— 它不需要知道。 要等它真的需要你的身分時，才會跟你要憑證。

登入 Gmail 的實際順序（這個順序很重要）：

  1. 瀏覽器先用 TLS 驗證伺服器 —— 確認你連到的是真的 Google
  2. 網址列旁出現鎖頭 = 伺服器驗過了
  3. 這時才出現輸入帳號密碼的畫面 —— 換伺服器驗證你

兩邊都驗過 = entity authentication。

課堂問答補充：有同學問「可不可以只驗收方？」 答案是可以。只驗一邊叫 server-side authentication， 雙向叫 mutual authentication。方向可以任選，看場景決定哪個合理。

💡 考試小心：老師講的 entity authentication， HAC 書上叫 identification（§1.7.1）。用詞不同、講的是同一件事。

§2.5 第四個目標：Non-repudiation（不可否認性）

意思：事後不能賴帳。

老師的例子（電影裡常見）：老闆口頭叫員工去做一筆交易， 結果賠了，老闆回頭說「我從來沒叫你做這件事」。

因為是口頭交代，沒有證據。可憐的員工完全無法自保。

有些系統會把 non-repudiation 列成設計目標，讓「我沒說過」這句話說不出口。

老師說這個目標會隨應用場景來來去去，不像 CIA 那樣每次都要。 細節等後面有具體例子時再談。

§3對稱式加密（Symmetric Key）

§3.1 一個 cryptosystem 的三個演算法

要達成 confidentiality，就要一套 encryption / decryption 系統。它有三個演算法：

演算法 符號 做什麼
Key generation — 從金鑰空間裡挑一把鑰匙出來
Encryption E 吃 (訊息, 金鑰) → 吐密文
Decryption D 吃 (密文, 金鑰) → 吐回原訊息

符號約定（注意大小寫，考試會用）：

符號 是什麼
K（大寫） key space，所有可用金鑰的集合
k（小寫） 從 K 裡實際挑出來用的那一把
M（大寫） message space，所有合法訊息的集合
C（大寫） ciphertext space，所有可能密文的集合

加密做的事：把訊息 M 變成另一段資訊，叫 ciphertext（密文）C。 解密做的事：拿密文，配上同一把金鑰，變回原本的訊息。

⚠️ 字幕辨識錯誤：PSI vertex / Cy vertex = ciphertext。

§3.2 Alice → Bob 走一遍

Alice                         (Eve 在偷看)                    Bob
  │                                │                           │
  │  C = E(k, M)                   │                           │
  ├────────────── 送出 C ──────────┼──────────────────────────►│
  │                                │                           │
  │                          看得到 C ✓                  M = D(k, C)
  │                          知道演算法 ✓                       │
  │                          但沒有 k ✗                        │

流程：

  1. Alice 算 C = E(k, M)
  2. 送出去的是 C，不是 M
  3. Bob 算 M = D(k, C) 還原

k 只有 Alice 和 Bob 有，是他們之前就共享好的。

Eve 的處境：他有 Wireshark，抓得到 Alice 和 Bob 之間所有往來。 他看得到 C，也知道用的是哪個演算法。但他沒有 k，所以還原不出 M。

💡 老師特別強調用詞：不要說「Eve 不可能解出來」， 要說「Eve 在不知道 k 的情況下還原出 M 的機率非常低」。 後面課程會實際算這個機率，你會看到它低到接近不可能 —— 但那是機率，不是絕對。

來源：影片二

§3.3 正確性條件

一個 cryptosystem 要能用，必須滿足：

對所有 k ∈ K、所有 M ∈ M：

D(k, E(k, M)) = M

白話：任何合法金鑰配任何合法訊息，加密再解密，要拿回一模一樣的東西。

為什麼要特別講這個：你可能寫出一個演算法，某些 key 用起來好好的， 換另一些 key 就壞掉。那就不是一個正確的加解密演算法。

來源：影片二

§4凱撒位移密碼（Caesar Shift Cipher）

§4.1 怎麼運作

年代：至少 2500 年前。現在看起來很粗糙，但當年是很好用的東西。

設定：

  • 英文字母 26 個（先不分大小寫）
  • 每個字母對到一個數字：a=0, b=1, c=2, ... z=25
  • 金鑰 k 是 0 到 25 之間的一個數字

加密：一個字元一個字元處理，每個都加上 k，然後 mod 26。

例子（老師課堂上算的那個）：

M   = a b c
k   = 1          （1 對應到字母 b）

a(0) + 1 = 1 → b
b(1) + 1 = 2 → c
c(2) + 1 = 3 → d

C   = b c d

解密：知道 k 之後，減回去就好。

mod 26 在幹嘛：確保結果永遠落在 0–25 之間。這是一個循環的集合， 超過 z 就繞回 a。老師說這個例子 k=1 太小，實際上沒真的用到 mod。

⚠️ 老師口誤：他說「金鑰可以選 0 到 255」。 凱撒密碼是 0 到 25（因為只有 26 個字母）。這個要記對。

⚠️ 字幕辨識錯誤：Asian way of encryption 的原意是 ancient（古老的）。 凱撒是羅馬人，跟亞洲無關。

§4.3 破法二：Statistical analysis（統計分析）

比暴力破解更快，而且完全不用試金鑰。

原理：英文裡字母出現的頻率很不平均。

  • 高頻：母音 e、a、i、o
  • 低頻：x、y、z

凱撒的弱點：它把每個字母固定平移同樣的格數。 這等於把「字母 i 的高出現頻率」整組搬到另一個字母上（例如搬到 h）。

怎麼破：看密文，發現 h 出現得特別多 → 那它原本大概是某個母音 → 往回推就知道位移了幾格。

關鍵洞見：加密沒有消滅統計特徵，只是把它搬家。

來源：影片二

§4.4 這裡學到的第一課

老師說講凱撒不是為了教這個古董，是為了帶出兩個原則：

原則 1：金鑰空間（key space）必須夠大

如果金鑰只有 26 種，沒人擋得住你寫一個跑 26 圈的 for 迴圈。

原則 2：好的密文要藏住原文的統計特徵

原文裡某些字母重複很多次，密文不該看得出來。

換成二進位講更清楚：

情況
原文 假設 1 的數量比 0 多很多
好的密文 0 和 1 的數量應該差不多
壞的密文 還是看得出 1 比 0 多 → 洩漏了原文的資訊

⚠️ 老師的用詞容易誤會：他說密文應該有 even number of zeros and ones。 意思是 0 和 1 的數量要「平均、差不多」， 不是「偶數個」。（even 在這裡是「均等」不是「偶數」。）

§5公開金鑰加密（Public Key / Asymmetric）

§5.1 為什麼需要它

對稱式有一個在真實網路上做不到的前提：雙方要事先共享一把金鑰。

老師的例子很好記：

你想連 gmail.com。你不可能走進 Google 辦公室說 「我們來對一把鑰匙吧，我回家要連你們的伺服器」。

Alice 和 Bob 如果是熟人，可以第一次見面時講好一把 k，之後上網都用它。 但使用者 vs 大型伺服器這種場景，完全行不通。

所以實務上用的是另一套：public key cryptography。

來源：影片二

§5.2 兩把鑰匙 + 公開目錄

Asymmetric（非對稱）：跟對稱式不同，每個人有兩把鑰匙。

鑰匙 放哪裡 誰看得到
Public key（公鑰） 發布到公開目錄 所有人
Secret key（私鑰） 自己藏好 只有本人

PKI（public key infrastructure）會有一個 repository / 公開目錄， 每個人把自己的公鑰放上去（就是一串 binary），任何人都能下載。 私鑰絕對不發布。

最重要的性質：

公鑰和私鑰之間有數學關聯， 但光有公鑰，要推出私鑰在計算上非常困難。

為什麼這條這麼關鍵：因為公鑰按定義就是人人看得到的。 如果從公鑰能推出私鑰，整套制度當場垮掉。 就是靠「推不出來」，你沒分享出去的私鑰才能一直安全地留在你手上。

兩把鑰匙的數學關係怎麼來的，是後面課程的內容。

§5.3 Alice → Bob 走一遍

        ┌──────── 公開目錄 ────────┐
        │  Alice 的公鑰  10110...  │
        │  Bob   的公鑰  10011...  │   ← 誰都能下載
        └──────────────────────────┘
                   ▲
                   │ ① 查 Bob 的公鑰
                   │
Alice ─────────────┴──── C = E(Bob 的公鑰, M) ────────────► Bob
                                                    M = D(Bob 的私鑰, C)
                          Eve 看得到 C ✓
                          也看得到 Bob 的公鑰 ✓（那本來就公開）
                          但沒有 Bob 的私鑰 ✗ → 解不開

流程：

  1. Alice 去公開目錄，查 Bob 的公鑰
  2. 用它加密要私下傳給 Bob 的訊息 → 得到 C
  3. 送 C 給 Bob
  4. Bob 用自己的私鑰解開，還原 M

Bob 要回信就反過來：去查 Alice 的公鑰，用它加密，送給 Alice。 這樣一來一往可以一直持續下去。

跟對稱式最大的差別：

Alice 完全不需要事先跟 Bob 共享金鑰。她只是去查了 Bob 的公鑰。

⚠️ 老師在這段口誤了兩次，考試別跟著錯：

老師說的 應該是
Alice 用 Bob 的公鑰 decrypt 訊息 encrypt（加密）
Eve 不知道 Bob 的 public key Bob 的 secret key（私鑰）

第二個特別要注意：公鑰是公開的，Eve 當然知道。 Eve 缺的是私鑰。老師後面自己就講對了 （"Eve doesn't know the secret key of Bob"）。

來源：影片二

§5.4 為什麼還是需要對稱式

看到公鑰這麼方便，會忍不住想：那對稱式是不是可以丟掉了？

答案是不行。理由是速度。

非對稱（公鑰）加密比對稱式慢很多。 例如 AES 比 RSA 快好幾倍。

所以實務上怎麼做（這個組合要記住）：

① 用公鑰（例如 RSA）→ 交換一把對稱金鑰
② 拿到金鑰後 → 大量資料改用對稱式（例如 AES）加密

不會用 RSA 去加密一個大檔案。

結論：

兩者是互補的，不是誰取代誰。 要有安全又有效率的通訊，兩個都需要。

§8這堂課的重點三句話

考前掃一眼用。

  1. 密碼學的目標是 CIA —— Confidentiality（讀不到）、Integrity（沒被改）、 Authentication（確認是誰）。加上第四個 Non-repudiation（不能賴帳）。

  2. 凱撒密碼教我們兩件事 —— 金鑰空間必須夠大（不然 for 迴圈就破）， 而且密文必須藏住原文的統計特徵（不然頻率分析比暴力破解還快）。

  3. 對稱式和公鑰是互補的，不是誰取代誰 —— 公鑰解決「沒見過面怎麼開始」， 對稱式解決「大量資料怎麼加得快」。實務上先用公鑰換一把對稱金鑰， 再用 AES 加密內容。
