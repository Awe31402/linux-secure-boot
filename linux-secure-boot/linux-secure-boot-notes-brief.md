## 2. Situation

- 這本書講的是**嵌入式 ARM 板子**的 secure boot：U-Boot、Yocto、i.MX8 / i.MX9、
  STM32MP1、CAAM 加密硬體、燒 fuse。
- **不是**一般 PC 那套 UEFI + shim + 微軟簽章。網路上搜「Linux secure boot」
  大部分是後者，兩者觀念相通但零件完全不同 —— 筆記要講清楚這個差別，
  避免日後查資料混淆。
- 作者假設讀者是資深嵌入式開發者，讀者本人不是。書裡當常識跳過的名詞
  （U-Boot SPL、fuse、CAAM 等）筆記要補一句白話解釋。

## 6. 頁碼對照：書頁 ↔ PDF 頁

**這本 PDF 的書頁與 PDF 頁差值不是固定的**，每章開頭會少一頁。
逐頁讀出 PDF 上印的頁碼後，實際對應如下：

| 書頁 | PDF 頁 | 位移 |
|---|---|---|
| 1–75 | 21–95 | +20 |
| 77–107 | 96–126 | +19 |
| 109–189 | 127–207 | +18 |
| 191–215 | 208–232 | +17 |
| 217–236 | 233–252 | +16 |

書頁 **76、108、190、216 在這個 PDF 裡不存在**（章節分隔頁未編號）。

> ⚠️ **教訓**：第一次只抽樣了幾頁就推論出「差值固定 +20」，
> 結果第 2、3 章的頁碼全錯。
> **規則：頁碼對照必須逐頁掃過整本 PDF 驗證，不得由少數樣本外推。**

重建對照表的作法：

```bash
for p in $(seq 21 252); do
  n=$(pdftotext -f $p -l $p linux-secure-boot.pdf - 2>/dev/null \
      | grep -E '^[0-9]{1,3}$' | tail -1)
  echo "$p ${n:-NONE}"
done
```

（每頁的頁碼印在該頁文字流的最後，所以取最後一個獨立的數字行。）

## 7. 網頁版怎麼建

網頁版是**從 markdown 建置產生的**，不是手寫的第二份內容 ——
所以 **markdown 是唯一真相來源，改完一定要重跑建置**。

- 建置腳本：`tools/build_notes_html.py`
- 版型樣板：`tools/notes_template.html`
- 產出：`linux-secure-boot-notes.html`（單一檔案，無執行期 JS 相依）

改完 markdown 後重跑：

```bash
python3 tools/build_notes_html.py
```

引言區塊靠開頭的符號分類上色：
`⚠️` 警告 · `🎯` 重點 · `📌` 書上明說的缺口 · `💡` 訣竅 · `ℹ️` 補充 · `📄` 原文引用。

> ⚠️ **相鄰的引言區塊會被 python-markdown 黏成一塊**，
> 分類會因此跑掉（例如兩段原文變成一段、上色錯誤）。
> 建置腳本裡的 `split_adjacent_quotes()` 會在兩個 `>` 區塊之間
> 自動插入 `<!-- -->` 隔開，所以手寫 markdown 時不用自己補。
> **但如果換掉建置流程，這件事要記得重做。**
